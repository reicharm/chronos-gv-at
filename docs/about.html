CHRONOS
Continuous Historical Record Of National Open-data Snapshots

Ein täglich aktualisiertes, diffbares Archiv der Metadaten aller offenen Daten von data.gv.at, dem offenen Datenportal der österreichischen Verwaltung. Für jeden Tag gibt es einen Commit und einen Tag — so lässt sich nachvollziehen, welche Datensätze neu hinzukamen, sich änderten oder verschwanden.

Wichtig: Archiviert werden die Metadaten (die DCAT-AP.at-Katalogeinträge: Titel, Beschreibung, Schlagworte, Distributionen, Herausgeber …) — nicht die eigentlichen Datendateien hinter den Distributionen. CHRONOS ist ein versioniertes Abbild des Katalogs, nicht der Nutzdaten selbst.

Wie es funktioniert

Ein GitHub-Actions-Workflow läuft täglich und

  1. lädt alle Datensätze über die Piveau Search API von data.gv.at (/api/hub/search/search) via Scroll vollständig herunter,
  2. legt eine JSON-Datei pro Datensatz ab, gruppiert in Unterordner je Katalog,
  3. schreibt Dateien nur bei tatsächlich geändertem Inhalt (deterministisches JSON → saubere, minimale Diffs),
  4. löscht Dateien von Datensätzen, die aus dem Portal verschwunden sind,
  5. erfasst zusätzlich alle Facetten als komprimierte Tages-Sicherung — Grundlage für beliebige spätere Visualisierungen,
  6. baut daraus die Dashboard-Daten und deployt die Seite auf GitHub Pages,
  7. committet den Tagesstand und setzt einen Datums-Tag snapshot-YYYY-MM-DD (an änderungslosen Tagen ein Keepalive-Commit).

Dadurch zeigt schon der geänderte Ordner-Teilbaum, in welchem Katalog sich etwas bewegt hat.

Repo-Struktur

.
├── .github/workflows/daily-archive.yml   # täglicher Workflow
├── dump_data_gv_at_perfile.py            # Volldump, 1 Datei je Datensatz
├── capture_facets.py                     # täglicher All-Facetten-Snapshot
├── build_dashboard_data.py               # baut docs/data.json
├── datasets/                             # das diffbare Archiv
│   ├── <katalog>/<dataset-id>.json
│   └── _index.json                       # Anzahl je Katalog
├── stats/                                # Facetten-Sicherung
│   ├── facets/<datum>.json.gz
│   └── facet-labels.json
├── docs/                                 # GitHub Pages
│   ├── index.html                        # Dashboard
│   ├── about.html                        # diese Seite
│   ├── chronos-mark.svg                  # Logo-Mark / Favicon
│   └── data.json                         # via Actions gebaut & deployt (nicht eingecheckt)
└── chronos-logo.svg                      # Logo-Lockup

Nutzung

Den heutigen Stand ansehen: durch datasets/ browsen. Änderungen nachvollziehen:

git log --oneline -- datasets/
git show <commit>                          # kompletter Tagesdiff
git show <commit> -- datasets/<katalog>/   # Änderungen eines Katalogs
git checkout snapshot-2026-08-14           # exakter Stand eines Tages
git log -p -- datasets/<katalog>/<id>.json # ein Datensatz über die Zeit

Datenquelle & Lizenz

Die Metadaten stammen von data.gv.at. Für ihre Nachnutzung gelten die dortigen Lizenz- bzw. Nutzungsbedingungen — bitte am Portal prüfen und die jeweilige Quelle entsprechend zitieren. Dieses Projekt ist ein inoffizielles Community-Archiv und steht in keiner Verbindung zum Betreiber von data.gv.at.

Hinweise

  • Metadaten, nicht Nutzdaten: siehe Kasten oben.
  • Kataloge vs. Stellen: Die größten „Kataloge" sind teils Harvester-Quellen (OHOLD, offenerhaushalt.at …); die veröffentlichende Stelle (Publisher) ist die inhaltlich nähere Achse.
  • Facetten-Sicherung: Alle Facetten werden täglich archiviert — spätere Visualisierungen (Themen, Formate, Sprachen …) sind rückwirkend möglich.
  • Pages via Actions: Die Seite wird als Actions-Artefakt deployt; data.json ist nicht eingecheckt, damit die Git-History schlank bleibt.
  • Größe: Der Workflow warnt ab 4 GB Repo-Größe; bei Bedarf hilft ein jährlicher History-Rollover.
